# MathGap diagnosis workspace — contribution and assistance record

Prepared September 16, 2026 for the diagnosis workspace source handoff.

## Existing project contributions

The source project supplied by Minglang already contained the capstone notebook-derived simulation and diagnosis engine, a saved trained model, synthetic datasets, the Streamlit research console, and a separate student web experience. The new diagnosis workspace reuses the existing engine and saved artifact. It does not claim that this implementation session created that underlying research method or trained a new model.

The repository's existing MIT notice names **Minglang and Qingyang Xiao**. That notice is retained in the package. Attribution here describes provenance; it does not independently determine legal authorship or change ownership.

## Minglang's direction

Minglang requested a separate diagnosis dashboard using the existing research code, asked for deeper design and animation research, and described the desired interface as a beautifully made tool that is compact, crisp, and tactile. Minglang initially selected **Precision Workbench**, then rejected the implemented design and requested further research across visual references, graphics, prompts, and YouTube design workflows, including Jack Roberts. Minglang subsequently authorized a full rebuild based on that research. The older concept is superseded and is not the current visual source of truth. The old student interface remains separate from this build.

Minglang then rejected the navy/cobalt/lilac rebuild and requested a more distinctive version using installed creative plugins and the built-in image generator. Codex generated three visual concepts and autonomously selected **Mathematical instrument studio** under that delegated direction. The v4 interface has horizontal navigation, chalk and graphite surfaces, vermilion accents, an open composition separated by rules, and self-hosted Geist Variable and Geist Mono Variable. It retains diagnosis-first navigation, authored mathematical figures and their supported controls, the inspector quick check, and highlighting of actual prerequisite paths. These choices describe the implementation; Minglang did not separately approve every visual detail.

## AI assistance in this implementation

Codex assisted with:

- Inspecting the existing code and documenting its inputs, output meanings, and limits.
- Researching interface design references, prompt examples, motion resources, and YouTube workflows; reviewing captions and sampled frames rather than claiming uninterrupted video viewing. The v4 rebuild uses a selected ImageGen concept as its visual reference, implemented as editable React and CSS rather than a rasterized interface.
- Implementing the React frontend, full-input FastAPI adapter, concept metadata, and authored worked examples.
- Rebuilding the surrounding interface, adding authored figures for all 14 supported concepts with controls on supported full-size figures, and implementing candidate navigation, inspector quick checks, and highlighting of existing graph relationships.
- Generating original editorial sculpture artwork with the built-in ImageGen tool and the Gamma connector. `public/art/connection-study.jpg` appears in the diagnosis hero; `public/art/loop-study.jpg` appears in About. Exact prompts and production-file provenance are included in `docs/rebuild-v4/ASSETS.md`. The tools did not expose a precise image-model version, so this record does not assign one.
- Adding automated API/contract checks and conducting implementation review. The current frontend suite has 30 passing tests: 9 workspace tests and 21 figure tests, including full-precision JSON export after a failed rerun, required input validation, and mathematical control behavior. V4 browser checks covered desktop, tablet, and phone layouts; actual-model presets; graph fit and selection; figure controls; and reduced motion. Both pages of the final Chrome-generated A4 review PDF were visually inspected.
- Preparing launch and source-packaging scripts and handoff documentation.

The concept definitions, worked examples, and mathematical figure implementations were drafted with AI assistance and checked for mathematical consistency during implementation. They are brief authored review material, not a validated curriculum or content generated by the model at runtime. Interactive figures illustrate mathematical relationships; they do not measure a student's understanding or alter model inputs. Test and browser-QA evidence should be read for what was actually checked; this record does not substitute for domain review.

V4 design records, verified screens, and the final two-page A4 review PDF are stored in `docs/rebuild-v4/`. `design-qa.md` records the completed browser, print, frontend-test, production-build, and static-hosting checks, including their limits. Evidence under `docs/rebuild-v3/`, screenshots directly under `docs/`, and earlier review PDFs is historical. The API and saved model were unchanged in v4; backend checks from earlier work are not presented as a new test run.

The UI libraries and reference sites are credited in the README. Installed agent design skills guided the development process but are not runtime application dependencies. No LLM API is called by this diagnosis workspace.

## Boundaries of the deliverable

The package contains a working interface around a synthetic research model. It does not add or claim real-student validation, measured mastery, adaptive question generation, authentication, billing, or cloud deployment. Scores remain alternative top-gap predictions, and the prerequisite map is an authored mathematical relationship graph.

This record is intended to support accurate explanation of the project and its development. It makes no claim about eligibility, compliance, judging outcomes, or acceptance by the Congressional App Challenge or any other program. Any submission description should identify the existing research work, Minglang's product/design decisions, third-party libraries, and the AI assistance actually used.
